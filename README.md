## About the book

This book explores data structures and algorithms through a hybrid approach that combines DRAKON visual programming with JavaScript. It is intended primarily for university students studying these subjects, and for teachers and programmers interested in a visual approach to understanding and implementing algorithms.

The central idea is to make the logic of an algorithm visible and connect it directly to executable code. Readers can examine a DRAKON-diagram, edit it in DrakonTech, generate JavaScript, and experiment with the resulting program.

## From a diagram to a working program

DRAKON diagrams are an integral part of the programming process. In DrakonTech, readers can work on an algorithm within its diagram and automatically generate JavaScript from it.

**Understand the problem → examine the diagram → modify the algorithm → generate JavaScript → run and test.**

For more complex algorithms, mind maps introduce the reasoning and organization of the solution before the detailed diagram. Explanations, illustrations, and selected videos support the study of operations and their behavior.

The book also considers how to choose a data structure for a particular task, taking account of the operations required and the organization of computer memory.

## How to use the book

1. **Read a topic** and identify the problem the algorithm is intended to solve.
2. **Trace the DRAKON diagram** using a small example. Predict the result before running the program.
3. **Study the generated JavaScript** alongside the diagram.
4. **Experiment in DrakonTech:** edit the diagram, generate the code again, and run the implementation.
5. **Test your understanding:** change the input, examine boundary cases, and explain why the algorithm behaves as it does.

Editable DRAKON diagrams and automatically generated JavaScript accompany the book on GitHub, enabling readers to study, modify, and run the implementations.

## Feedback and corrections

This is the first public version of a substantial work. Errors and omissions are possible, and readers' feedback will help improve it.

I would especially appreciate hearing:

- Did the diagrams help you understand an algorithm? Which example was most useful?
- Were you able to modify a diagram and run the generated JavaScript?
