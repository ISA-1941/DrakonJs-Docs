How to Conduct the Experiment

Goal: Discover how input order and array size influence the computational cost of sorting.

  1. Select Insertion Sort or Selection Sort. Keep Random seed = 42 throughout the study.
  2. Set N = 100. Before running, predict: which input order will require the most comparisons?
  3. Click Run Sorted + Reverse + Random. Three rows will appear in the results table.
  4. Set N = 200 and click the same button again. Do not click Clear results — the earlier rows must remain.
  5. Select Nearly sorted, set N = 100, and click Run experiment. Repeat with N = 200.
  6. Compare Comparisons and Data movements at the same N. Then compare N = 100 and 200 using Growth exponent (p). Explain whether your prediction was correct.

Experiment progress: 0 / 8

The 8 required runs are counted separately for the currently selected algorithm: four input types × two array sizes (100 and 200), with seed 42. Progress shows the required results currently in the table. You can also explore other sizes independently.

Buttons: Run experiment = one selected input type; Run Sorted + Reverse + Random = three input types; Clear results = erase all measurements; Previous/Next state = inspect intermediate arrays for N ≤ 30. Running the same combination again updates its row.

Experiment settings

All input types are generated from the same seeded random permutation of 1…N. Nearly sorted: about 1% of random pair exchanges from sorted order. Large quadratic runs may take time. The same seed makes results reproducible.
